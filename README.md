# ChatGPT Timezone Guard (ChatGPT / Codex 时区与反降智守护工具)

> **优雅解决 ChatGPT / Codex 桌面客户端因本地时区与代理 IP 不一致导致的隐性“降智”风控。**  
> **零修改系统时区 · 零开启全局 TUN 模式 · 毫秒级动态对齐节点时区 · 国内网络千兆满速**

---

## 🎯 痛点背景

### 1. 为什么会被“降智”？
在使用 ChatGPT 桌面客户端或 Codex 应用时，OpenAI 后端会采集客户端上报的环境元数据（包括系统时区、语言和上报时间）。
* 当你的**代理节点 IP 位于海外（如美西/日本/新加坡）**，而**客户端环境时区为中国标准时间（UTC+8）**时，极易触发反欺诈与风控策略；
* **隐性降智**：模型不会直接报错，表面上界面依然显示为高阶模型，但在后端被静默降级为低算力轻量模型，丢失深度思考过程（Thinking 链），回答草率简陋。

### 2. 为什么网上的传统方法“代价极大”或“容易失效”？
- ❌ **直接改操作系统全局时区**：杀敌一千自损八百。电脑上的微信消息时序错乱、钉钉打卡异常、日历提醒错乱、本地代码文件的修改时间戳全部失真。
- ❌ **直接开启代理软件的全局 TUN 模式**：TUN 虚拟网卡会接管系统 DNS。国内绝大多数网站和 CDN 调度失效，访问百度、Bilibili、淘宝被分配到海外 CDN，国内网络卡成 PPT。
- ❌ **简单的单行启动命令**：如果后台有未退出的残留进程，系统会直接唤醒老进程，导致时区根本注入失败；如果未豁免本地回环，会导致客户端内部通信断裂，陷入无限“重新连接”。

---

## 💡 解决方案与核心机制

本工具通过精细化的进程控制与网络参数注入，实现了**“单软件完全沙盒化隔离”**：

```
[ 你的电脑 (macOS / Windows) ]
 ├── 操作系统全局时区：中国标准时间 (UTC+8)  <-- 完好无损
 ├── 国内网络流量：千兆宽带直连 (微信/B站/办公) <-- 毫秒直达，不卡顿
 └── 🚀 ChatGPT / Codex 专属沙盒进程
      ├── 时区：动态注入节点时区 (如 America/Los_Angeles)
      ├── 代理：定向注入指定本地端口 (如 7897 / 7890)
      ├── 防泄露：强制 socks5h 远端 DNS 解析 (杜绝 DNS Leak)
      └── 本地保护：no_proxy 豁免 127.0.0.1 (保护应用内部 IPC 握手)
```

## 🚀 快速上手

### 🍎 macOS 用户（推荐制作专属桌面图标）

#### 步骤 1：准备脚本
克隆本仓库到本地，或直接下载 `scripts/macos/launch_chatgpt.sh`：
```bash
git clone https://github.com/A5he1ter/chatgpt-timezone-guard.git
cd chatgpt-timezone-guard/scripts/macos
chmod +x launch_chatgpt.sh
```

#### 步骤 2：使用 Automator（自动操作）制成桌面 App（推荐）
1. 按 `Cmd + 空格` 搜索并打开系统自带的 **自动操作 (Automator)**；
2. 选择 **“新建文稿”** -> 选择 **“应用程序”** -> 点击“选取”；
3. 在左侧资源库搜索 `shell`，将 **“运行 Shell 脚本”** 拖拽到右侧工作区；
4. 将 `scripts/macos/launch_chatgpt.sh` 的完整内容粘贴进编辑框；
5. 按 `Cmd + S` 保存，命名为 **`ChatGPT (Pro)`**，保存到“应用程序”或“桌面”。

以后需要使用 ChatGPT 时，**只需双击桌面图标**：
* 屏幕右上角会自动弹出通知提示：*“已自动匹配节点时区: America/Los_Angeles (代理端口: 7897)”*；
* 启动完成后脚本进程自动退出销毁，不占任何后台资源。

---

### 🪟 Windows 用户

## 🧪 验证与效果测试

启动进入软件后，**新建一个空白对话**，通过以下两步验证：

### 1. 验证时区是否生效
在输入框提问：
> **“请告诉我你当前检测到的客户端具体时间、时区和星期几？”**

* ✅ **成功**：回答中明确显示你代理节点对应的城市与时区（如 `America/Los_Angeles (EDT / UTC-04:00)` 或 `Asia/Tokyo`）；
* ❌ **失败**：如果依然回复北京时间（UTC+8），说明老进程未被杀干净，请完全退出后重试。

### 2. 验证降智是否解除
观察回答上方是否出现了 **“用时 XX 秒 >”**（深度思考 / Thinking 链展开）。满血高阶模型拥有严密的思维链，逻辑题会展开详尽推导，不再草草敷衍。

## 🛠️ 常见踩坑与技术排错手册 (FAQ)

### Q1：启动时弹出 `Route Error (400 Invalid content type: text/html)`？
* **原因**：这是因为应用发出的登录/认证 API 请求没有走代理，直连被 Cloudflare 拦截并返回了 HTML 人机验证页面。
* **解决办法**：
  1. 确认你代理软件的真实本地端口（例如 Clash Verge 默认是 `7897`，原版 Clash 通常是 `7890`，Surge 是 `6152`）；
  2. 脚本已内置动态探测，如需手动修改，可在脚本开头将 `PROXY_PORT` 更改为你的实际端口。

### Q2：发消息时聊天界面一直显示“正在重新连接 (Reconnecting...)”？
* **原因**：ChatGPT 客户端内部界面是通过本地回环（`127.0.0.1` 上的本地 WebSocket / IPC）与后台核心服务通信的。如果代理环境变量把本地地址也代理了，本地通信就会被发到外部代理，导致握手死循环。
* **解决办法**：脚本中已严格声明 `no_proxy="localhost,127.0.0.1,*.local"`，必须确保本地回环被豁免。

### Q3：为什么需要关注 `ab.chatgpt.com` 分流？
* **原因**：`ab.chatgpt.com` 是 OpenAI 的 A/B 测试、灰度发布与遥测网关。如果代理规则里仅精确匹配了 `DOMAIN,chatgpt.com`，会导致 `ab.chatgpt.com` 走直连并超时卡死 30 秒。
* **解决办法**：在代理客户端的分流规则中，务必使用 **`DOMAIN-SUFFIX`（后缀匹配）**：
  ```yaml
  - DOMAIN-SUFFIX,chatgpt.com,PROXY
  - DOMAIN-SUFFIX,openai.com,PROXY
  - DOMAIN-SUFFIX,oaistatic.com,PROXY
  - DOMAIN-SUFFIX,oaiusercontent.com,PROXY
  ```
